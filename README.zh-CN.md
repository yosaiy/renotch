# Re:notch · 简体中文与 Codex 扩展

基于 Re:notch v1.7.0 开发，保留原 MIT 许可证。本分支增加简体中文界面、Codex 多任务与账号用量、多显示器跟随和 QQ 音乐联动。界面当前固定使用简体中文，未提供运行时语言切换。

## 使用方式

- 启动 Codex 桌面应用与 Re:notch。本机执行中的任务会自动出现在刘海中。
- 展开后默认展示全部活动任务：待回答优先，其次为待批准，再显示执行中任务。
- “全部”“待你处理”“执行中”可切换筛选；任务数量不设展示上限，列表可滚动。
- 每张卡片显示任务标题、项目、状态。待回答的问题可展开查看完整内容及选项。
- “去回答”“去确认”“打开任务”打开对应的 Codex 任务。回答与批准均在 Codex 中完成。
- 异步提问期间，如果 Codex 仍在运行，卡片会显示“后台仍在执行”。
- 已结束任务默认保留 2 分钟，在“已结束”中折叠展示。
- 面板显示 Codex 账号剩余额度，“详情”中显示重置时间与各模型额度。每分钟自动刷新，也可手动刷新；数据不可用时明确提示，保留旧数据时会标注。
- 展开面板右上角的齿轮进入设置。界面、设置标签、说明、提示与辅助功能文案使用简体中文；应用名、项目名、任务原文与协议字段保持原样。

## Codex 配置

在“设置 → 通用 → Codex 任务”中调整：

| 界面参数 | 默认值 | 功能 |
| --- | --- | --- |
| 显示 Codex 任务状态 | 开启 | 显示全部本机执行中、待回答、待批准的任务 |
| 显示问题摘要 | 开启 | 在卡片内显示问题，并允许展开选项 |
| 显示剩余用量 | 开启 | 按账号实际返回的周期显示剩余百分比、重置时间和模型专属额度 |
| 保留已结束任务 | 2 分钟 | 可选择不保留、2 分钟或 10 分钟 |

原版的外观、显示器、尺寸、间距、计时器与专注设置已保留并汉化。尺寸单位为 macOS 逻辑点。旧版设置能够继续读取，无需重置。

“设置 → 通用 → 显示器与时间 → 显示器模式”提供两种选择：

- **固定到指定显示器**：默认选择，使用“目标显示器”指定的屏幕，未指定则固定在主显示器。显示器断开后回到主显示器，保留原选择。
- **跟随前台窗口**：切换应用窗口或把前台窗口移到另一块屏幕时自动跟随。跨屏窗口以占用面积最大的屏幕为准；没有可用窗口时保留上次位置。操作 Re:notch 自身不会改变跟随目标。

跟随模式下目标显示器选项暂时禁用，切回固定模式后恢复之前的选择。跟随仅使用窗口几何信息，不读取窗口标题或图像，不需要新增辅助功能或录屏权限。

## QQ 音乐联动

- 支持本机 QQ 音乐，自动显示歌曲、歌手、专辑、封面、播放状态与进度；可播放／暂停、上一首、下一首，也可直接打开 QQ 音乐。
- 与 Apple Music、Spotify 共用原有音乐卡片，优先展示最近开始播放的来源。QQ 音乐只有成为系统“正在播放”的来源时才显示和接收控制，避免误控别的播放器。
- QQ 音乐的进度仅供查看；音量、跳转进度、随机与循环模式在 QQ 音乐内调整。暂停时保留最近读到的进度；启动时若无法读取暂停位置，会显示“进度暂不可用”。系统没有提供封面时显示音乐占位图。
- 通过本机媒体桥接读取系统媒体状态；组件由应用携带，用 macOS 自带 Perl 加载，不额外安装运行库，不需要辅助功能或录屏权限。只传递 QQ 音乐的曲目数据，不联网搜索封面、不读取 QQ 账号或缓存数据库。
- 依赖 macOS 内部 MediaRemote 接口，未来系统或 QQ 音乐升级可能需要适配。接口声明参考 [Theos MediaRemote 头文件](https://github.com/theos/headers/blob/master/MediaRemote/MediaRemote.h)；兼容性方案参考 [Fastfetch 的媒体读取实现](https://github.com/fastfetch-cli/fastfetch/blob/dev/src/detection/media/media_apple.m)。本项目的桥接代码独立实现。

## 构建与验证

需要 macOS 与 Swift 6 工具链。项目运行时最低系统要求为 macOS 13。

```sh
scripts/build-music-bridge.sh
scripts/test.sh
scripts/test-codex.sh --live
scripts/test-usage-display.sh --live
CODE_SIGN_IDENTITY=- scripts/build-app.sh
```

直接使用 `swift run Renotch` 调试 QQ 音乐时，应先运行 `scripts/build-music-bridge.sh`。应用打包脚本会自动构建并携带媒体桥接组件。

`test.sh` 包含原有冒烟与 AppModel 测试，以及 76 项 Codex 状态检查、25 项额度与显示器检查、37 项 QQ 音乐检查。状态 `--live` 只读连接本机 Codex，输出任务 ID、状态与问题数；额度 `--live` 只读查询账号额度，不输出凭据、任务正文或工具日志。

构建结果为 `dist/Re:notch.app`，包含 Apple 芯片与 Intel 两种架构。`CODE_SIGN_IDENTITY=-` 表示本地临时签名，未进行 Apple 公证。重新签名后，系统可能要求重新授予原有的日历或音乐控制权限。

调试构建支持 `--codex-ui-preview`，展示 14 个明确标注的示例任务，便于检查长标题、问题展开、筛选与滚动。示例不写入 Codex，发布构建不包含此入口。

## 接入方式与边界

- 状态来自 Codex 桌面应用的本机 IPC 状态流；数据库只用于发现任务 ID，并以只读方式打开。
- 不根据数据库中的旧运行标记直接判断任务仍在执行。收到实时快照后才显示状态。
- 只订阅本机根任务，避免把内部子智能体重复列成用户任务；目前不包含远程主机或云端任务。
- 识别同步提问与异步提问。异步问题的答复依据已接受的用户消息逐项消除，互不影响。
- 每个任务维护独立的修订号与状态，消息缺失时重新获取快照，连接中断时清除旧状态并重连。
- 不向 Codex 发送答复、批准或任务控制指令，不修改 Codex 的配置、数据库或审批行为；状态与问题摘要只在内存中处理。
- 额度通过已安装的 Codex CLI 只读调用 `account/rateLimits/read`，沿用 Codex 自己的登录状态。Re:notch 不读取凭据，不购买额度、不消耗重置次数、不修改账号配置。
- 剩余百分比为 `100 - usedPercent`，优先使用 `rateLimitsByLimitId`。不假设主周期一定是五小时，不把未提供的周期或空值当作零额度。通用额度和模型专属额度分别展示。
- 此接入使用桌面应用的内部接口，并非公开稳定 API。已适配本机桌面版本 26.908.70816、内置 CLI 0.154.0-alpha.6.2、状态流版本 11；未来升级可能需要适配。出现不兼容时会显示中文提示。
- 本分支功能尚未包含在上游 v1.7.0 安装包中；从上游发布页安装该版本会恢复原版功能。

## 布局修正

Codex 面板默认至少为 620 × 460 逻辑点，任务列表独立滚动。展开和收起内容均使用实际面板尺寸，修复内容仍按原版高度计算造成的裁切、底部大块空白与内边距异常。切换筛选会回到列表顶部，长标题与问题可换行；列表按稳定任务 ID 更新，避免每次输出都重新排序。

多显示器环境按所选模式定位，不再因为普通状态刷新而意外跨屏移动。
